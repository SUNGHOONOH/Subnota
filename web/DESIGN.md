# Subnota 랜딩 — 디자인 시스템

**Last verified: 2026-08-15**

이 문서는 `web/`(마케팅 사이트)만 다룬다. 제품 UI의 권위는
`desktop/docs/design.md` 에 있고, 이 문서는 그것을 **소비**할 뿐 바꾸지 않는다.

## 핵심 결정: 랜딩은 제품의 재료로 짓는다

랜딩은 제품 스크린샷을 얹은 마케팅 페이지가 아니다. 페이지 자체가 앱과 같은
재료(같은 토큰, 같은 컴포넌트 문법, 같은 절제)로 만들어진다. 방문자가 보는
첫 화면의 질감이 설치 후 첫 화면의 질감과 같아야 한다.

따라서 이 사이트에는 **마케팅 전용 디자인 언어가 없다.** 그라디언트, 글래스,
3D, 거대한 아이콘 카드, 네온 강조는 앱에 없으므로 여기에도 없다.

## 두 개의 층

| 층 | 무엇 | 토큰 출처 |
| --- | --- | --- |
| 제품 층 | 실제 앱 화면 재현 (`.subnota-app` 이하 전부) | `app/subnota-ui/tokens.css` — 앱 토큰의 이식본 |
| 페이지 층 | 헤더·챕터 제목·CTA·푸터 | `app/globals.css` — 제품 층에서 파생 |

**제품 층은 손대지 않는다.** 클래스 이름과 값은 `desktop/src/styles/` 에서
그대로 옮겨온 것이고, 앱이 바뀌면 여기가 따라간다. 반대 방향은 없다.

페이지 층 선택자는 **반드시 자기 블록 안에서 끝나야 한다.** `.chapter h2` 처럼
느슨하게 쓰면 무대 안의 `.session-header h2`(15px)까지 잡아 40px로 만든다 —
실제로 한 번 그렇게 됐다. 그래서 페이지 층은 `.chapter-head h2`,
`.detail-section > p` 처럼 자식 결합자나 전용 클래스로만 쓴다.

같은 이유로 섹션 여백은 `padding: X 0` 이 아니라 `padding-block: X` 를 쓴다.
단축 속성은 `.shell` 의 좌우 여백까지 0으로 지워 좁은 화면에서 글자가 화면
끝에 붙는다.

## 색

제품 층은 앱 값 그대로. 페이지 층은 앱 값에서 파생시키되, 대비 때문에 두 개만 조정한다.

| 역할 | 값 |
| --- | --- |
| 페이지 바탕 | `#ffffff` — 앱 캔버스와 같은 면 |
| 카드 무대 바탕 | `#faf9f7` |
| 본문 잉크 | `#2c2520` |
| 흐린 글자 (페이지 층) | `#6b6255` |
| 선 (페이지 층) | `#e0dcd0` |
| 브랜드 (잉크 블루) | `#325496` |
| 로고 마크 / 오른쪽 잎 | `#4c71b7` / `#0b6e4f` |

페이지 층의 흐린 글자와 선 두 값만 앱 토큰에서 파생시켰다. 앱의
`--app-color-muted(#9c8e7c)` 는 종이 바탕 위에서 3.2:1이라 본문 옆 보조
텍스트로 쓸 수 없다 — 색상각은 유지한 채 명도만 내려 4.5:1을 넘겼다.
선도 같은 이유로 한 단계 진하다. 제품 층 안에서는 앱 값을 그대로 쓴다.

브랜드색은 앱과 같은 규칙으로 아낀다: focus 링, 진짜 링크, 캘린더의 오늘,
선택 메모 레일. **그 외 전부 중립.**

헤더의 주 행동은 앱이 승인한 **다크 잉크 버튼**(`#1d1d1f`)이고 다운로드는
OS 스토어 배지 형태다. 브랜드 블루를 여기 쓰지 않는 이유는, 그 색이 제품
화면 안에서 "지금 여기"를 가리키는 데 이미 배정돼 있어서다 — 페이지가 같은
색을 쓰면 화면 안의 표시가 묻힌다.

### 색 배경판

챕터마다 제품 창이 색 배경판 위에 떠 있다(`.showcase-blue/green/amber/clay`).
배경판 색은 그 챕터 본문의 하이라이트 칩 색과 짝을 이룬다 — 색이 챕터를
구분하는 유일한 장치이므로 둘이 어긋나면 짝이 깨진다.

| 챕터 | 배경판 / 하이라이트 |
| --- | --- |
| 관련 기억 | blue |
| 메모 → 일정 | green |
| 수집과 재사용 | amber |
| 작업 흐름 | clay |

### 주석 층은 예외다

형광펜(`.marker`)과 손글씨 메모(`.hand-note`)는 앱 팔레트 밖의 잉크와 다른
서체(Nanum Pen Script)를 쓴다. 앱 UI가 아니라 **그 위에 사람이 펜으로 표시한
층**이기 때문이다. 앱의 `의도된 팔레트` 카브아웃과 같은 성격이므로 이것들을
앱 토큰으로 흡수하지 말 것.

지키는 선:

- 제품 화면(`.subnota-app`) **안으로 들어가지 않는다.** 무대 위에 얹힐 뿐이다.
- 형광펜은 글자를 감싸는 **칩**이다(배경 + 같은 계열 글자색, radius 4px).
  밑줄 띠도 시도했으나 한국어 본문에서는 칩 쪽이 또렷하게 읽힌다.
- 손글씨 주석은 **한 챕터에 하나까지**. 화면마다 붙이면 표시가 아니라 장식이
  된다. 900px 아래에서는 화면을 가리므로 빠진다.

## 서체

- 본문/UI: **Pretendard** (앱과 동일)
- 워드마크: **Alegreya Sans** — 마크 옆 글자에만. 앱의 Quick Subnota·로그인과
  같은 얼굴이다. 본문에 쓰지 않는다.

굵기는 400 / 500 / 600 / 700에서 멈춘다. 위계를 800·900으로 보상하지 않는다.
랜딩 제목은 앱보다 클 수 있지만(최대 56px) 굵기 규칙은 같다.

## 페이지 순서

```
Hero → About → Features(챕터 4개) → 다운로드
```

헤더는 `Features` 드롭다운(4개 챕터) + `About` + 다운로드 CTA. 드롭다운의
각 줄은 앱 아이콘 + 이름 + 한 줄 설명이다.

## 섹션 문법

챕터 표시는 대문자 트래킹 eyebrow가 아니라 **앱의 탭 칩**(`.split-editor-tab`
모양)이다. 페이지가 자기 문법을 새로 만들지 않고 제품의 문법을 빌린다.

한 챕터의 구성은 고정이다:

```
탭 칩(챕터 이름)
제목 (40–56px / 600)
한두 줄 설명
대표 기능 화면 1개  ← 이 챕터에서 가장 큰 것
더보기 링크
```

대표 기능 화면보다 큰 요소를 챕터에 두지 않는다. 나머지 기능은 전부
`/features/*` 상세 페이지로 간다 — 메인에서 아코디언으로 펼치지 않는다.

상세 페이지의 추가 기능은 **카드 격자**다(`FeatureGrid` + `FeatureCard`).
카드 위쪽 무대에 실제 UI 조각(`Piece`)을 살짝 기울여 겹쳐 놓고, 아래에 제목과
설명이 온다. 조각은 앱에서 그대로 떼어 온 것이라 확대·축소하지 않는다 —
카드 밖으로 잘려 나가는 것은 허용한다.

구분은 헤어라인(`--app-color-border`) 하나. 섹션마다 배경색을 바꾸지 않는다.

## 제품 화면 프레임

대표 흐름은 **색 배경판 위에 뜬 창**(`SceneShowcase`)으로 보여준다. 창은
배경판의 88% × 80%를 차지하고, 배경판 비율은 창 + 여백에서 역산하므로 안쪽
화면이 잘리거나 남는 자락이 생기지 않는다. 맥 신호등과 가운데 제목은 창을
창으로 읽히게 하는 최소한의 표시다.

관계가 요점인 챕터(메모 → 일정)는 창 하나 대신 **조각 둘**을 나란히 놓는다
(`SceneStage` + `.fragment-scene`). 앱 전체를 보여줄 필요가 없고, 두 화면
사이의 이동이 주제라서다. 팝오버만은 실제 앱 그대로 붙인다.

앱 화면은 고정 논리 크기(**1080×620**, 조각은 1080×560)로 그리고 컨테이너 폭에 맞춰 통째로
축소한다(`.scene-stage` + ResizeObserver). 요소마다 반응형 값을 새로 정하지
않는 이유는, 그 순간 앱의 28px 컨트롤과 13px 글자가 무너져 다른 앱이 되기
때문이다.

- 높이가 앱 창 실제 비율보다 낮은 것은 의도적이다. 640으로 두면 본문 아래가
  텅 빈 흰 면으로 남는데, 실제 작업창은 그렇게 비어 있지 않다.
- 배율에는 **상한 1** 이 있다. 없으면 논리 폭이 좁은 작은 장면이 컨테이너를
  채우려고 확대되어, 상세 페이지의 추가 기능이 대표 흐름보다 커지고 앱의
  13px 글자가 20px로 그려진다. 축소만 하고 확대는 하지 않는다.
  `.shell` 안쪽 폭(1080)을 무대 논리 폭과 같게 잡아 둔 것도 이 때문이다 —
  넓은 화면에서 배율이 정확히 1.0이 되고 본문 왼쪽 끝과 프레임 왼쪽 끝이
  한 선에 선다.
- 배율에는 **하한(0.62)** 도 있다. 그 아래로 줄이면 13px UI가 5px가 되어
  아무것도 읽히지 않는다. 하한에 걸리면 프레임 **안에서** 가로로 넘기고,
  좁은 화면에서는 사이드바 대신 본문이 먼저 보이도록 한 번 밀어 둔다.
  페이지 본문은 어떤 폭에서도 옆으로 밀리지 않는다.
- 브라우저 크롬이나 macOS 메뉴바 목업을 씌우지 않는다 — 앱은 hiddenInset이라
  그런 것이 없다.

앱에서 별도 창이나 포털로 뜨는 것(Quick Subnota, 날짜 팝오버, 선택 팝오버)은
`.subnota-app` 바깥, 무대 위에 얹는다. 그래서 토큰은 `.subnota-app` 과
`.scene-stage` **양쪽**에 걸어 둔다 — 앱 안에만 걸면 그것들이 배경을 잃는다.

프레임은 1px 헤어라인 + 얕은 그림자. 큰 그림자를 쓰지 않는다.

## 모션

- 챕터당 **대표 애니메이션 정확히 하나**, 8–11초 루프.
- 타이핑은 진행률로 자르지 않고 **한 글자씩** 찍는다(`useTyping`). 간격을
  조금 흔들어야 사람이 치는 것으로 읽힌다.
- 스크롤로 화면에 들어올 때 재생, 나가면 멈춘다.
- `prefers-reduced-motion: reduce` 에서는 마지막 프레임 정적 렌더. 스텝뿐
  아니라 framer 의 진입·전환도 함께 멎어야 하므로 `MotionProvider` 가
  `MotionConfig reducedMotion="user"` 로 한 곳에서 끈다. 손글씨 화살표는
  framer 가 `stroke-dasharray` 를 인라인으로 쓰므로 CSS 에서 한 번 더 막는다.
- 앱과 같은 이징: 짧은 전환 140–200ms, 진입/이탈은 spring `duration 0.3 / bounce 0`.

## 하지 않는 것

- 새 마케팅 팔레트, 그라디언트, 글래스, 3D, 네온
- 아이콘 + 제목 + 설명 카드를 페이지 구조로 쓰기
- macOS 메뉴바 / Safari 창 / iPhone 목업
- 내부 구현 용어 노출 — 임베딩, 벡터, KNN, 청크, State A/B, Ambient Mirror
- 제공하지 않는 기능 주장 (iOS 동기화 포함)
- `~하는 순간` 반복 제목
